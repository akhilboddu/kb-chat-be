# Knowledge Source Tracking

This document explains the knowledge source tracking feature that has been added to the knowledge base system.

## Overview

The `knowledge_base_documents` table now includes a `knowledge_source` column that tracks where each piece of content originated from. This provides better traceability and allows filtering content by source.

## Knowledge Source Types

The system now tracks the following source types:

- **`website`** - Content scraped from websites using the web scraper
- **`file`** - Content extracted from uploaded files (PDF, DOCX, TXT, etc.)
- **`human conversation`** - Knowledge added by human agents during conversations
- **`api`** - Content added via the JSON API endpoint
- **`agent`** - Knowledge generated by the AI agent itself
- **`manual`** - Default for direct additions (fallback)
- **`unknown`** - For existing records before this feature was added

## Database Changes

### Migration

A new migration file has been created: `supabase/migrations/002_add_knowledge_source_tracking.sql`

This migration:
1. Adds the `knowledge_source` column to `knowledge_base_documents`
2. Creates an index for efficient filtering by source
3. Sets existing records to have source = 'unknown'
4. Adds a descriptive comment to the column

To apply the migration:
```bash
# Option 1: Through Supabase Dashboard
# Go to SQL Editor and run the migration SQL

# Option 2: Using helper script to see the SQL
python scripts/apply_knowledge_source_migration.py
```

### Updated Schema

```sql
knowledge_base_documents {
  id: uuid
  kb_id: text
  document_id: text
  content: text
  ctx_text: text
  embedding: vector(768)
  metadata: jsonb
  knowledge_source: text  -- NEW COLUMN
  created_at: timestamptz
}
```

## Code Changes

### 1. Knowledge Base Manager

The `supabase_kb_manager.py` has been updated:

```python
# populate_kb now accepts knowledge_source parameter
populate_kb(kb_collection, text_chunks, knowledge_source="manual")

# add_to_kb now accepts knowledge_source parameter
add_to_kb(kb_id, text_to_add, metadata=None, knowledge_source="manual")
```

### 2. Source Tracking by Feature

- **Web Scraping** (`scrape_service.py`):
  ```python
  kb_manager.add_to_kb(kb_id, text_to_add, knowledge_source="website")
  ```

- **File Upload** (`file.py`):
  ```python
  kb_manager.add_to_kb(kb_id, text_to_add, knowledge_source="file")
  ```

- **Human Conversation** (`bot.py`, `chat.py`):
  ```python
  kb_manager.add_to_kb(kb_id, text_to_add, knowledge_source="human conversation")
  ```

- **API JSON Upload** (`agent_service.py`):
  ```python
  kb_manager.add_to_kb(kb_id, extracted_text, knowledge_source="api")
  ```

- **Agent Generated** (`tools.py`):
  ```python
  kb_manager.add_to_kb(kb_id, text_to_add, knowledge_source="agent")
  ```

### 3. Knowledge Sources Table

The `knowledge_sources` table (different from the column) is also updated when scraping websites to maintain a high-level record of sources per bot.

## Utility Scripts

Three helper scripts have been created in the `scripts/` directory:

### 1. `check_knowledge_sources.py`

Provides an overview of knowledge sources across all KBs:

```bash
# Check all knowledge sources
python scripts/check_knowledge_sources.py

# Check sources for a specific KB
python scripts/check_knowledge_sources.py kb_1234567890_abcd
```

Output example:
```
Overall Knowledge Source Summary:
----------------------------------------
  file: 125 documents
  human conversation: 42 documents
  website: 87 documents
  unknown: 234 documents

Total documents: 488
```

### 2. `view_kb_sources.py`

View detailed documents with their sources for a specific KB:

```bash
# List all knowledge bases
python scripts/view_kb_sources.py list

# View documents for a specific KB (default 10)
python scripts/view_kb_sources.py kb_1234567890_abcd

# View more documents
python scripts/view_kb_sources.py kb_1234567890_abcd 20
```

### 3. `apply_knowledge_source_migration.py`

Helper script to display the migration SQL:

```bash
python scripts/apply_knowledge_source_migration.py
```

## Benefits

1. **Traceability**: Know where each piece of knowledge came from
2. **Filtering**: Can filter KB content by source type
3. **Quality Control**: Distinguish between human-verified and automated content
4. **Analytics**: Understand the composition of your knowledge base
5. **Debugging**: Easier to track down issues with specific content

## Future Enhancements

1. **Source Metadata**: Add additional metadata per source (e.g., URL for websites, filename for files)
2. **Source Quality Scores**: Rate sources based on reliability
3. **Source-based Retrieval**: Prefer certain sources during retrieval
4. **Source Filtering in Queries**: Allow agents to query only specific sources
5. **Source Analytics Dashboard**: Visual breakdown of KB composition

## Backward Compatibility

- Existing records are marked as 'unknown' source
- The `knowledge_source` parameter defaults to 'manual' if not specified
- No breaking changes to existing API endpoints
